WhisperTranscribe

ローカル PC 上で動作する音声・動画ファイル文字起こしツール

録音機が分割した複数ファイルをひとまとめにし、Whisper による文字起こしまでを1アプリで完結

https://github.com/NamakeroBK/WhisperTranscribe
Windows 10/11 .NET 8 WPF Whisper.net 1.9 ffmpeg CPU / CUDA / Vulkan 無料 Colab GPU

1. このアプリでできること

▲ 処理パイプライン全体図
  • 音声ファイル（WAV/MP3/M4A/FLAC/OGG等）・動画ファイル（MP4/MOV/MKV/AVI等）の文字起こし
  • 録音機が30分単位などで分割した複数ファイルを順序通りに連結
  • 録音レベルのばらつきをラウドネス正規化で均す
  • 32bit float WAV など Whisper が直接読めない形式を自動変換
  • モデル（精度と速度のトレードオフ）を GUI からダウンロード・切り替え
  • 出力は .txt / .srt / .vtt 形式
  • インターネット不要で動作（初回のみ ffmpeg とモデルの取得のため接続が必要）
  • 無料 Colab GPU で高速処理する半手動連携機能あり（§13）

2. 動作環境

項目要件
OSWindows 10/11 x64
.NET.NET 8 Desktop Runtime

通信初回 ffmpeg・モデル DL のみ

3. インストール

バイナリ利用の場合

GitHub Releases からビルド済み ZIP をダウンロードし、任意のフォルダに展開。

ソースからビルド

git clone https://github.com/NamakeroBK/WhisperTranscribe.git
cd WhisperTranscribe
dotnet build -c Release

生成物:

  • GUI: bin\Release\net8.0-windows\WhisperTranscribe.exe
  • CLI: TestRunner\bin\Release\net8.0\wtcli.exe

6. CLI版（wtcli）の使い方

バッチ処理・スクリプトからの呼び出し用にコマンドラインインターフェースも用意しています。

基本

wtcli <input> [--model NAME] [--lang LANG] [--prompt TEXT] [--hq] [--no-norm] [--out DIR]

例

# 1ファイルを日本語・smallモデルで文字起こし
wtcli "C:\rec\meeting.m4a" --model small --lang ja

# 複数ファイルを連結して文字起こし
wtcli "C:\rec\part1.wav" "C:\rec\part2.wav" "C:\rec\part3.wav" --model large-v3-turbo

# 高品質モード + 初期プロンプト
wtcli "C:\rec\interview.mp3" --model large-v3 --hq `
      --prompt "本日のインタビューでは、新製品の開発経緯についてお話を伺います。山田取締役、田中エンジニアにご登壇いただいています。"

オプション一覧

オプション説明デフォルト
--model NAMEモデル名 (tiny / base / small / medium / large-v3 / large-v3-turbo)small
--lang LANG言語コード (ja / en / auto 等)ja
--prompt TEXTinitial_prompt（例文を渡す）なし
--hq高品質モード (beam_size=10)OFF
--no-normラウドネス正規化を無効化正規化ON
--out DIR出力フォルダ入力と同じ場所

環境変数

変数意味例
WHISPER_RUNTIMEランタイム優先順（カンマ区切り）Cuda,Cpu / Cpu / CpuNoAvx

7. モデルの選び方

▲ サイズと色は ★円のサイズ＝モデルサイズ。色＝相対的な精度
モデルサイズ速度日本語精度用途
tiny77 MB最速△試運転・速報
base148 MB速い△内容把握
small488 MB中○デイリー用途のバランス型（おすすめ）
medium1.5 GB遅い◎議事録など
large-v33.0 GB最遅◎◎最高精度

🎯 迷ったら large-v3-turbo日本語精度はほぼ large-v3 と同等で、速度は small と medium の中間。

8. 初期プロンプトの書き方

Whisper の initial_prompt は「指示文」ではなく「模範的な書き起こし例」として書きます。最大 224 トークン（日本語で約 150〜180 文字）。

守るべき3つの原則

原則内容
①「指示」を書かない。「丁寧に書き起こしてください」のようなお願いは無意味（GPTのプロンプトとは別物）
②句読点付きの完成文を 2〜3 文含める。これにより出力にも句読点が付く
③固有名詞・専門用語は 10〜15 語に絞る。多すぎるとハルシネーション（誤生成）の原因

✅ 良い例（会議録音）

本日の経営会議では、第3四半期の業績報告と新製品のリリーススケジュールについて議論しました。
出席者は、山田CEO、佐藤CFO、田中マーケティング部長、開発チームの鈴木リーダーです。

❌ 悪い例

  • 「ですます調で書き起こしてください」
    ← 指示は効きません
  • 固有名詞リスト 50 個
    ← 多すぎ、ハルシネーション誘発
  • 200 文字超の長文
    ← トークン上限で切り捨て
⚠️ 効果の検証はモデルにより異なるtiny/base では効果が薄く、small 以上で顕著に効きます。large-v3-turbo + 適切な initial_prompt が最強の組合せ。

12. トラブルシューティング

Q. アプリ起動直後にネイティブクラッシュ（exit code 0xC0000409 など）

GPU ランタイム（Vulkan/CUDA）の自動選択に失敗している可能性があります。CLI 版を環境変数付きで起動してください。

$env:WHISPER_RUNTIME = "Cpu"
wtcli input.wav --model small

または CpuNoAvx（古い CPU 向け）も試してください。GUI 版の場合、システム環境変数に WHISPER_RUNTIME=Cpu を設定してから再起動。

Q. 「ffmpeg.exe が見つかりません」

右上の「ffmpeg取得」ボタンを押す、または手動で %LOCALAPPDATA%\WhisperTranscribe\ffmpeg\ に ffmpeg.exe / ffprobe.exe を配置します。

Q. モデルダウンロードが途中で止まる

ネットワーク不安定や HuggingFace 側のリトライ等が原因です。%LOCALAPPDATA%\WhisperTranscribe\models\ に残った .part ファイルを削除して再実行してください。

Q. 文字起こしが極端に遅い

  • モデルが大きすぎる: medium / large 系は CPU だと数倍時間がかかります。small か large-v3-turbo に下げる
  • 高品質モードが ON: beam=10 は処理が約2倍重くなります
  • CPU が古い: 第4世代 Core より前は AVX2 が無く、CpuNoAvx ランタイム経由で動作するため遅い場合があります

Q. 出力テキストに句読点がない／変な単語が混ざる

初期プロンプトを活用してください（§8）。特に句読点については、句点を含む完成文を 2〜3 文プロンプトに入れることで改善されます。

Q. 大量ファイルを連結すると時間がかかる

デコード + concat + loudnorm の前処理はファイル数と総時間に比例します。ラウドネス正規化が不要な場合は OFF にすると倍速程度になります（CLI なら --no-norm）。

13. Colab 半手動連携（無料 GPU 利用）

NVIDIA GPU を持たない PC でも、Google Colab の無料 T4 GPU を使って高速に文字起こしできます。CPU 比 5〜15 倍速。

準備（初回のみ）

Google Drive のマイドライブ直下に次のフォルダを作ります（中身は空でOK）:

/MyDrive/WhisperTranscribe/inbox/    ← WAV をアップロードする場所
/MyDrive/WhisperTranscribe/outbox/   ← 結果が出力される場所

ワークフロー全体図

▲ Colab 半手動連携の全工程

使い方

  1. アプリにファイルを追加（通常通り）
  2. 右上の 「Colab前処理」 ボタンを押す
    • アプリが連結・正規化・16kHz変換を実行
    • %USERPROFILE%\Documents\WhisperTranscribe_Colab_Inbox\ に最終 WAV を出力
    • エクスプローラーがそのフォルダを表示し、ブラウザで Colab Notebook が開く
  3. エクスプローラーの WAV を Google Drive の inbox/ にドラッグ&ドロップ
  4. ブラウザの Colab Notebook で:
    • 上部メニュー: ランタイム → ランタイムのタイプを変更 → GPU (T4) を選択
    • 「4. 設定」セルを開き、必要なら MODEL LANGUAGE INITIAL_PROMPT を編集
    • メニュー: ランタイム → すべてのセルを実行 (Ctrl+F9)
    • Drive のマウント承認ダイアログが出たら許可
  5. 完了すると outbox/ に .txt .srt .vtt が生成される（Notebook の最後のセルで PC へ直接ダウンロードも可）
  6. アプリに戻り、右上の 「結果SRT読込」 ボタンから取得した SRT を選択

Notebook の特徴

  • モデル: 初期値 large-v3-turbo（GPU で1分音声 ≒ 6〜10秒）
  • VAD フィルタ: 無音区間スキップで処理高速化
  • 推奨パラメータ適用: temperature=0.0, condition_on_previous_text=False（幻覚抑制）
  • 対応形式: WAV/MP3/M4A/FLAC（アプリが WAV を吐くので通常 WAV）

Colab 無料枠の制限

項目制限
連続セッション最大 12 時間
アイドル切断約 90 分操作なしで切断
GPU 種別T4 が割当（混雑時は CPU のみになることも）
月間利用上限厳格な数値非公開、ヘビーユーザーには制限
⚠️ GPU 未割当の場合Notebook の最初のセル !nvidia-smi の出力で T4 が割り当てられたか確認できます。「No GPU found」の場合はランタイムタイプ変更で GPU を選択してください。

よくある質問

Q. Drive にアップロードした WAV が Notebook から見えない

マイドライブの直下に WhisperTranscribe フォルダが必要です。/MyDrive/Apps/... などにあると Notebook の探索パスと合いません。

Q. 「No CUDA GPUs are available」エラー

ランタイム → ランタイムのタイプを変更 で GPU を選び、ランタイム → ランタイムを再起動して再実行。

Q. メモリ不足エラー（large-v3 でクラッシュ）

設定セルで COMPUTE_TYPE = 'int8_float16' に変更すると VRAM 使用量が半減。または MODEL = 'large-v3-turbo'（既定）の方が軽量で実用的。
